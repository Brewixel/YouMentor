# YouMentor — backend-сервис бронирования менторских сессий

[English version](README.md)

YouMentor — backend-сервис на ASP.NET Core для создания, бронирования и отмены менторских сессий.

Основной фокус проекта — бизнес-правила, авторизация, конкурентное изменение данных и интеграционное тестирование с PostgreSQL.

## Что показывает проект

- ASP.NET Core Minimal APIs на .NET 10
- PostgreSQL и Entity Framework Core
- JWT-аутентификация через Keycloak
- авторизация на основе ролей и policies
- бизнес-правила внутри доменной модели
- optimistic concurrency при одновременном бронировании
- точечный retry через Polly
- unit- и integration-тесты с Testcontainers
- локальная инфраструктура в Docker
- CI через GitHub Actions

## Основные сценарии

| Пользователь | Операция | Главное правило |
|---|---|---|
| Ментор | Создать сессию | Сессия должна начинаться в будущем |
| Студент | Забронировать сессию | Забронировать можно только свободную будущую сессию |
| Ментор | Отменить сессию | Отменить её может только владелец до начала |
| Несколько студентов | Одновременно забронировать сессию | В базе должно сохраниться только одно бронирование |

Доменная модель `Session` управляет переходами состояния и предотвращает некорректные операции: например, бронирование уже занятого слота или отмену начавшейся сессии.

## Безопасное конкурентное бронирование

Два студента могут одновременно попытаться забронировать одну свободную сессию.

YouMentor использует optimistic concurrency в EF Core и отдельный Polly pipeline. После concurrency-конфликта приложение очищает устаревшее tracked-состояние, повторно загружает сессию и заново проверяет бизнес-правила.

Pipeline повторяет только `DbUpdateConcurrencyException`. Ошибки валидации, авторизации и обычные доменные конфликты не повторяются.

[Подробнее об обработке concurrency](docs/concurrency.ru.md)

## Авторизация

API проверяет JWT access tokens, выпущенные Keycloak.

- Ментор может создавать сессии.
- Студент может бронировать сессии.
- Отменить сессию может только создавший её ментор.
- Все endpoints сессий требуют аутентифицированного пользователя.

[Подробнее об аутентификации и авторизации](docs/authentication.ru.md)

## Архитектура

```text
API
 └── Application
      ├── Domain
      └── Application interfaces
           ▲
           │ реализует
           │
      Infrastructure
           └── PostgreSQL
```

Решение разделено на четыре основных проекта:

- `Domain` — сущности, переходы состояний, инварианты и типы результатов
- `Application` — команды, запросы, валидация, specifications и orchestration
- `Infrastructure` — EF Core, конфигурация PostgreSQL и миграции
- `Api` — endpoints, аутентификация, авторизация, обработка ошибок и DI

[Подробнее об архитектуре](docs/architecture.ru.md)

## Тестирование

Интеграционные тесты запускаются с настоящим PostgreSQL-контейнером и применяют реальные миграции EF Core.

Для сценариев, зависящих от времени, используются `TimeProvider` и `FakeTimeProvider`, благодаря чему тесты остаются детерминированными.

Pull requests в ветку `dev` автоматически собираются и тестируются через GitHub Actions.

[Подробнее о стратегии тестирования](docs/testing.ru.md)

## Текущее состояние

Сейчас проект поддерживает:

- создание, поиск, бронирование и отмену сессий;
- JWT-аутентификацию и ролевую авторизацию;
- проверку владельца защищённого ресурса;
- optimistic concurrency;
- точечный retry конфликтов бронирования;
- доменные, application- и integration-тесты.

Ближайшие итерации — завершить concurrency-тесты, добавить ограниченный retry в отмену там, где он оправдан, и публиковать `SessionBooked` через MassTransit и RabbitMQ.
