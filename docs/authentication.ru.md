# Аутентификация и авторизация

[English version](authentication.md) · [Вернуться к README](../README.ru.md)

## Аутентификация

YouMentor работает как OAuth 2.0 / OpenID Connect resource server.

Keycloak выпускает JWT access tokens. API проверяет:

- issuer;
- audience;
- срок действия токена;
- signing key;
- role claims.

Настроенный audience — `youmentor-api`, роли читаются из claim `roles`.

## Модель авторизации

Все endpoints сессий требуют аутентифицированного пользователя.

Сейчас настроены две policies:

- `MentorOnly` требует роль `mentor`;
- `StudentOnly` требует роль `student`.

| Операция | Требование |
|---|---|
| Создать сессию | роль `mentor` |
| Получить список сессий | аутентифицированный пользователь |
| Забронировать сессию | роль `student` |
| Отменить сессию | роль `mentor` и проверка владельца |

## Текущий пользователь

Application handlers не разбирают JWT claims напрямую. Они зависят от `ICurrentUser`, который предоставляет идентификатор текущего пользователя из request context.

Это отделяет application-код от `HttpContext` и позволяет в тестах подставлять аутентифицированные и неаутентифицированные сценарии.

## Проверка владельца ресурса

Одной проверки роли недостаточно для отмены. Handler также убеждается, что текущий ментор является владельцем выбранной сессии.

Поэтому ментор с корректной ролью не может отменить чужую сессию.

## Локальная настройка Keycloak

Среда разработки пока требует вручную создать realm, client, roles, пользователей и mapping роли в token claim. Подробности — в [инструкции по локальной разработке](local-development.ru.md).
