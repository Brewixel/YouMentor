# Стратегия тестирования

[English version](testing.md) · [Вернуться к README](../README.ru.md)

YouMentor использует доменные, application- и integration-тесты для проверки бизнес-поведения и persistence.

## Доменные тесты

Доменные тесты проверяют сущность `Session` без ASP.NET Core и базы данных.

Они покрывают:

- корректное и некорректное создание сессии;
- переходы состояния при бронировании;
- переходы состояния при отмене;
- некорректные идентификаторы и duration;
- ограничения, зависящие от текущего времени;
- нормализацию времени в UTC.

## Application-тесты

Application-тесты проверяют поведение handlers вокруг текущего пользователя, ожидаемых типов результатов, доменных правил и сохранения данных.

Fake-реализации позволяют явно проверять аутентифицированные и неаутентифицированные сценарии.

## Интеграционные тесты с PostgreSQL

Integration-тесты используют Testcontainers для запуска настоящего PostgreSQL-контейнера.

Тестовое окружение:

1. запускает изолированный PostgreSQL;
2. создаёт EF Core context с Npgsql и snake_case naming;
3. применяет реальные миграции приложения;
4. выполняет сценарий;
5. читает сохранённое состояние через отдельный context.

Так проверяется provider-specific поведение, которое не воспроизводит in-memory база.

## Детерминированное время

Production-код зависит от `TimeProvider`, а не обращается к системным часам напрямую.

Тесты используют `FakeTimeProvider`, поэтому сценарии будущих и уже начавшихся сессий выполняются с фиксированным временем без задержек и flaky-предположений.

## Concurrency-тесты

Текущий набор проверяет сохранение бронирования и доменные конфликты. Отдельные тесты выполнения Polly retry, исчерпания retry и одновременных конкурирующих бронирований являются следующей итерацией.

## Continuous integration

Pull requests в `dev` запускают GitHub Actions: restore зависимостей, сборку solution и выполнение тестов.

Запуск всех тестов локально:

```bash
dotnet test YouMentor.slnx
```

Docker должен быть доступен, потому что integration-тесты создают PostgreSQL-контейнер.
